3. CITIZEN REPORT VIEW
==================================================

Implement a complete working report form.

Required fields:

- Photo upload / camera input if supported by the current browser
- Category
- Description
- GPS latitude
- GPS longitude
- Location accuracy if available

Categories should come from the actual supported backend contract.

The user must be able to:

1. Select/take a photo.
2. Get browser GPS permission.
3. See the captured coordinates.
4. Select a civic issue category.
5. Enter a description.
6. Submit the report.

Use the existing:

POST /api/v1/sync/report

API contract.

The request must include the required fields expected by the backend, including:

- idempotency_key
- category
- photo_base64 when a photo is supplied
- latitude
- longitude
- accuracy_meters
- location_source
- description
- client_timestamp

Generate a proper UUID/idempotency key for each submission.

Do NOT hardcode a report ID.

5. MUNICIPAL DASHBOARD
==================================================

Build the dashboard using ONLY real API responses.

Use:

GET /api/v1/analytics/overview

for summary metrics.

Use:

GET /api/v1/incidents

for the priority incident list.

Use:

GET /api/v1/map/incidents

for map data.

Use:

GET /api/v1/incidents/{incident_id}

for incident details.

Use:

GET /api/v1/incidents/{incident_id}/why-score

for the score explanation.

Do not create frontend arrays containing fake incidents.
